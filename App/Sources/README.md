# Модули ihatecrypto

Одна папка — один модуль SwiftPM. Зависимости идут внутрь: протоколы и цепочки не знают про интерфейс и модели.

```
IhatecryptoApp/               окно: чат, баланс, блоки, настройки, импорт адресов
IhatecryptoCore/              план сделки: парсер фраз, риск, блоки, котировки для показа
LLM/…                  доступ к моделям (см. LLM/README.md)

Wallet/Core            BIP-39, вывод ключей EVM и Solana, Keccak, EIP-712, подпись secp256k1
Wallet/Check           `swift run WalletCheck …` — живые проверки на тестовом кошельке
Chains/Solana          RPC, переводы SOL и SPL, ATA, разбор транзакций, таблицы адресов, сборка из инструкций
Chains/EVM             RLP, транзакции EIP-1559, ERC-20, газ; Arbitrum
Protocols/Hyperliquid  MessagePack, подписи ордеров и переводов, отправка
Protocols/OneClick     NEAR Intents 1Click: котировка, депозит, статус, привязка адреса
Protocols/Relay        мост Relay: Solana ⇄ Hyperliquid за секунды (депозиторий, привязка заказа)
Protocols/Jupiter      свапы в Solana
DeFi/JupiterLend       хранилища Jupiter Lend Earn: депозит, вывод, позиции
Execution              рамка подтверждения и журнал «запись до отправки»
Execution/Trade        исполнение плана: подготовка с симуляцией → мост Relay → плечо → вход → стоп и тейк → проверка на бирже; закрытие
Guard                  последняя проверка перед подписью
Signer/API             протокол XPC между приложением и процессом подписи
Signer/Service         процесс подписи: seed в Keychain, разбор, Guard, подпись (без сети, в песочнице)
```

## Сборки

- `./run.sh` — быстрая сборка для разработки, без процесса подписи (кошелёк только на просмотр).
- `./build-app.sh [Release|Debug]` — `ihatecrypto Dev.app`, копия для разработки, со встроенным `Signer.xpc` через `Xcode/project.yml` (XcodeGen), подпись командой N78L833HCS. Она стоит рядом с рабочей `ihatecrypto.app` (релиз: `release.sh`, обновляется сама) и ничего с ней не делит: bundle id `app.ihatecrypto.mac.dev` даёт свою группу Keychain (свои кошельки), свои настройки и входы в модели; из кода (`Flavor`, Canvases.swift) — своя папка данных `Application Support/ihatecrypto-dev`, порт debug API 51790 и агент Keep running. Release ставится в `~/Applications/ihatecrypto Dev.app`; рабочую копию скрипт не трогает. `Tools/uitest.py` ходит в Dev-копию (`IHATECRYPTO_APP=work` — в рабочую).
- Самопроверка процесса подписи на тестовой фразе: `open -W --stdout /dev/stdout ".build/xcode/Build/Products/Debug/ihatecrypto Dev.app" --args -signerSelfTest YES` (флаги запуска есть только в Debug-сборке). Запускать через `open`: при запуске бинарника напрямую launchd не видит XPC-сервис.

## Исполнение

`Executor.prepare` берёт свежие цены и балансы, применяет правила риска (`IhatecryptoCore/Risk.swift`), строит транзакцию моста и симулирует её до подписи: из этого окно подтверждения показывает, что изменится в каждом балансе. `execute` подписывает через `TradeSigner` (в ihatecrypto.app — процесс подписи, в терминале — тестовый ключ), пишет журнал до отправки и после каждого шага. Если стоп не встал на бирже, позиция сразу закрывается. В терминале: `WalletCheck execute "<фраза>" [--yes]`, `close ETH --yes`, `position`.

Jev проверяет команду модели против сообщения, готовый план против слов пользователя и список подписей с изменениями балансов против плана (`GuardJev/JevReviewer`). Он может только предупредить: когда на ответы, кроме «всё верно», приходится половина вероятности или больше; пользователь подтверждает предупреждение отдельной галочкой. Решает код. Порядок в запросе задаётся явно (сначала то, по чему судить, в конце то, что судят; варианты ответа — в двух порядках, ответы усредняются), а для команды Jev получает раздел справочника форм (`ChatRouter.forms(for:)`): без него он не знал, что `lend` — это Jupiter Lend. Замеры и размеченные наборы — `App/Tools/jevcheck` (`WalletCheck jev-eval`).

## Команды в чате

`IhatecryptoCore/PositionCommand.swift`: к открытой позиции — «стоп в безубыток», «стоп на X», «тейк на X», «закрой половину», «закрой», «отмени лимит»; после входа «стоп 2%», «тейк ближе» двигают ордера на бирже. Деньги — «выведи N USDC в Solana», «положи/сними N USDC из хранилища», «купи SOL на N USDC», «продай весь эфир», «покупай SOL на N USDC каждую неделю», «останови покупки». Спот только по проверенным адресам `SpotAsset.all`. Трейлинг, безубыток после частичного тейка (`Guardian.swift`) и расписание работают, пока открыт ihatecrypto. Торговый ключ (агент Hyperliquid) создаёт и хранит процесс подписи; им подписываются ордера без Touch ID, вывести им нельзя.

## Браузер для dApp

`IhatecryptoApp/Browser`: WKWebView, в страницу до её скриптов встраивается кошелёк Solana (Wallet Standard и старый `navigator.wallets`) и EVM (EIP-1193, EIP-6963). Каждый запрос — через окно подтверждения; транзакции Solana разбираются, симулируются, неизвестные программы подписываются только после отдельного разрешения (`extraPrograms` процессу подписи). EVM: вход (`personal_sign`) и простые typed data; процесс подписи сам считает хэш из JSON (`WalletCore/TypedData.swift`) и отклоняет Permit/Permit2, вложенные типы и слепые хэши; EVM-транзакции (`eth_sendTransaction`): calldata разбирается (`EVMChain/EVMCall`), безлимитный approve, setApprovalForAll, permit и transferFrom со своего адреса отклоняются и в приложении, и в процессе подписи; вызов проверяется через eth_call, газ оценивается, транзакцию собирает и подписывает процесс подписи. `SiteCheck` помечает адреса, похожие на известные dApp. Jev (`JevReviewer.site`) — второе мнение о сайте и транзакции. Тест: `WalletCheck browser-test-page <path>` и ihatecrypto.app с `-openBrowser file://… -browserAutoApprove YES -browserResultAfter 40`.

## Риск-менеджмент

Только криптовалюты Hyperliquid. Жёсткое правило: убыток на стопе не больше 2% капитала (Solana USDC + счёт Hyperliquid + хранилища), лимит меняется в настройках. Предупреждения: прибыль/риск ниже 1:1,5, стоп меньше ATR 4ч, плечо выше 5×, ликвидация ближе двух стопов, больше 5% движения за сутки перед входом, дорогой фандинг, маржа больше половины капитала. «Как учат»: стоп 1,5 ATR 4ч, тейк 2R, риск 1% капитала.

## Процесс подписи

Приложение не получает ключ. Оно шлёт `SignerRequest` (JSON в одном XPC-вызове), процесс подписи сам разбирает транзакцию и прогоняет Guard. Для переводов Hyperliquid схему EIP-712 выбирает он же по типу действия. Адреса токен-счетов, которые называет приложение, пересчитываются. Seed лежит в data-protection Keychain в группе `N78L833HCS.app.ihatecrypto.mac.signer`; с Touch ID системное окно показывает суммы и адреса из разбора процесса подписи. Одобренных получателей и таблицы адресов Solana пока сообщает приложение: у процесса подписи нет сети.

## Guard: защита от подменённых адресов

Код, а не модель: модель можно обмануть текстом на странице, проверку по списку — нет.

- **Solana:** транзакция разбирается по инструкциям. Разрешены только программы из списка (System, Compute Budget, SPL Token, Associated Token, Jupiter Swap, Jupiter Lend). Деньги могут уходить только на ваши счета или на адрес, привязанный к одобренной котировке. Разрешения на токены, смена владельца и чужие плательщики запрещены, приоритетная комиссия ограничена.
- **Симуляция:** перед отправкой транзакция прогоняется в сети, и балансы после неё сравниваются с одобренными. Так ловится маршрут, который внутри программы отправляет выход не вам.
- **1Click:** адрес депозита сверяется с тем, что 1Click сам привязал к нему: ваш получатель, адрес возврата, активы и сумма.
- **Relay:** разрешён только `deposit_token`/`deposit_native` программы Relay Depository от вашего кошелька; котировка должна называть ваших отправителя и получателя; адрес депозитория на Hyperliquid зашит и сверяется с `/chains` Relay.
- **Hyperliquid:** торговые действия внутри счёта разрешены, переводы наружу — только на одобренный адрес; одобряется только ваш ключ агента.

- **Входящий текст:** до парсера и модели — локальные правила (команды ассистенту, «переведи на адрес») и, если включено, классификатор Jev (`Guard/Jev`, OpenRouter Decisions API). Jev может только остановить текст: он не снимает находку правил и не разрешает подпись. Ему говорят, кто говорит: сообщение самого пользователя (его приказы ассистенту — норма, ищется вставленный чужой текст) или то, что принёс поиск модели — описание токена, документация сервиса, ответ API, строка контракта (`Workspace.screenedLookup`, `InjectionGuard.lookupProblem`): текст, который обращается к ассистенту или толкает деньги на свой адрес, модель не получает совсем. Сообщение читает Jev, когда в нём адрес, ссылка или оно длиннее 100 знаков; ответы поисков `token`, `services`, `service`, `call`, `rpc`, `hl`, `fetch` — всегда, остальные проходят только локальные правила.

Отправка в сеть принимает только `GuardedTransaction`, которую создаёт проверка, поэтому обойти её нельзя случайно.

## Новый протокол DeFi

Папка `DeFi/<Протокол>/`, цель в `Package.swift`, программа протокола в списке `SolanaGuard.knownPrograms` и правила балансов в команде проверки. Общий тип хранилища выделяется, когда появится второй протокол.

## Windows (ветка `windows`)

Ядро — всё, кроме `IhatecryptoApp` и `Signer/Service`, — собирается и проходит тесты вне Apple. Mac-сборка от этого не меняется: блок `#if !os(macOS)` в конце `Package.swift` убирает окно, XPC-подписанта и Sparkle и подключает swift-crypto (тот же API, что у CryptoKit).

Только на Mac (закрыто `#if`): Touch ID (`Presence.touchID` вне Mac — `false`), XPC-клиент подписанта, Ledger по USB и Bluetooth и транспорт к эмулятору Speculos (BSD-сокеты), OAuth-сервер для входа через браузер (вне Mac — ошибка «connect with an API key»), Apple Intelligence. Вне Mac `URLSession.bytes` отдаёт ответ модели целиком, а не по словам (`LLM/Core/Networking.swift`).

Дальше: seed через DPAPI и Windows Hello, процесс подписи на named pipe с тем же JSON (`SignerRequest`/`SignerReply`), интерфейс на Tauri + веб, Ledger через Windows HID, установщик и подпись Authenticode.

Проверка: GitHub Actions `.github/workflows/windows.yml` на каждый пуш в `windows`; локально — Linux-контейнер `swift:6.2` (OrbStack), в нём те же swift-crypto и corelibs Foundation.
